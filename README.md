# audit-agent – AI-агент проверки договоров и закрывающих документов

Набор навыков (Skills) для Claude Code, предназначенный для
комплексной проверки договоров и закрывающих документов
ИТ-компании, занимающейся заказной разработкой ПО.

Агент работает с Markdown-файлами, полученными из PDF скриптом
`pdf2md.py`, и выполняет юридический аудит, кросс-документарную
сверку, финансовый и налоговый контроль, проверку русского
языка и семантическое сравнение версий договоров.

## Возможности

Агент реализует шесть специализированных навыков, каждый из
которых решает отдельную задачу проверки документов:

| Навык | Назначение |
|-------|------------|
| `contract-legal-review` | Юридический аудит договора: ответственность, права, расторжение, gap-анализ |
| `cross-doc-reconcile` | Кросс-документарная сверка: суммы, реквизиты, ссылочность, подписанты |
| `financial-tax-check` | Финансовый и налоговый контроль: НДС, арифметика, условия оплаты |
| `russian-proofreading-check` | Проверка орфографии, грамматики, пунктуации и описок без изменения документов |
| `version-diff-semantic` | Семантическое сравнение версий договора: что изменилось и в чью пользу |
| `audit-summary` | Оркестратор: запуск всех проверок и формирование сводного отчёта |

**Ключевые особенности:**

- **Локальный запуск.** Работает с локальными LLM через Ollama
  (`qwen3.8:27b` рекомендуется для MacBook M1 Pro 32 ГБ) или
  с облачными моделями.
- **Без изменения документов.** Навыки только диагностируют
  проблемы и формируют отчёты, не внося правки в проверяемые
  файлы.
- **Модульность.** Каждый навык — отдельный `SKILL.md`, который
  можно дорабатывать независимо.
- **Русскоязычная специфика.** Учтены нормы русского языка,
  российское налоговое законодательство (НДС), особенности
  деловых документов.
- **Специфика IT-аутсорсинга.** Проверки адаптированы под
  договоры разработки ПО: права на код, open-source,
  SLA, этапная оплата.

Claude Code при старте читает описания (`description`) всех
навыков и загружает нужный, когда запрос пользователя совпадает
с триггерами. Навык можно вызвать и явно через слэш-команду
(`/contract-legal-review`).

## Требования

### Обязательные

- **Claude Code** — CLI-инструмент Anthropic.
  [Установка](https://docs.anthropic.com/claude-code)
- **Ollama** — для локального запуска моделей.
  [Установка](https://ollama.com/download)
- **Python 3.9+** — для скрипта `pdf2md.py`.
- **PDF-файлы документов** — договоры, акты, счета, счета-фактуры.

### Аппаратные (для локального запуска)

| Компонент | Минимум | Рекомендуется |
|-----------|---------|---------------|
| RAM | 16 ГБ | 32 ГБ |
| SSD | 50 ГБ свободно | 100 ГБ свободно |
| CPU/GPU | Apple Silicon или x86_64 | Apple M1 Pro / M2 / M3 |

### Модели

- **Локальная (рекомендуется):** `qwen3.8:27b` — оптимальный
  баланс качества и потребления памяти (≈18 ГБ) для MacBook
  M1 Pro 32 ГБ.
- **Альтернатива (юридическая точность):** `gemma4:26b`.
- **Облачная:** `gpt-oss:120b-cloud` — максимальное качество,
  требует интернет.

## Установка

### 1. Клонирование репозитория

```bash
git clone https://github.com/your-org/contract-audit-agent.git
cd contract-audit-agent
```

### 2. Установка зависимостей Python

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
requirements.txt:
```text
pdfplumber>=0.10.0
markdownify>=0.11.0
```

### 3. Установка Ollama и модели

```bash
# Установка Ollama (macOS)
brew install ollama

# Запуск сервера
ollama serve

# Загрузка модели (в отдельном терминале)
ollama pull qwen3.8:27b
```

### 4. Размещение навыков

Навыки уже находятся в `.claude/skills/` репозитория. Claude Code
подхватит их автоматически, если запущен из корня проекта.

Для глобального доступа (все проекты) скопируйте их в
`~/.claude/skills/`:

```bash
cp -r .claude/skills/* ~/.claude/skills/
```

## Настройка

### Конвертация PDF в Markdown

Поместите PDF-файлы в директорию (например, `./docs/`) и выполните:

```bash
python pdf2md.py ./docs/
```

Скрипт создаст `.md`-файлы в той же директории (или в
поддиректории `md/` — в зависимости от реализации скрипта).

### Запуск агента

```bash
# Локальная модель
ollama launch claude --model qwen3.8:27b

# Или облачная модель
ollama launch claude --model gpt-oss:120b-cloud
```

После запуска вы попадёте в интерактивный чат Claude Code.
Убедитесь, что рабочая директория — корень проекта (там, где
лежит `.claude/skills/`).

### Проверка загрузки навыков

В чате агента выполните:

```text
/skills
```

или запросите:

```text
Какие навыки доступны?
```

Claude должен перечислить шесть навыков из `.claude/skills/`.

## Использование

### Быстрый старт: полный аудит комплекта

```bash
# 1. Конвертировать PDF
python pdf2md.py ./docs/

# 2. Запустить агента
ollama launch claude --model qwen3.8:27b

# 3. В чате агента:
/audit-summary ./docs/
```

Результат: `./reports/audit-report-docs.md` со сводкой
критических рисков, предупреждений и замечаний.

### Примеры вызова отдельных навыков

#### Юридический аудит договора

```text
/contract-legal-review ./docs/contract.md
```

Выявляет риски в разделах ответственности, прав 
на интеллектуальную собственность, расторжения.
Сохраняет `./reports/audit-report-contract.md`.

#### Кросс-документарная сверка

```text
/cross-doc-reconcile ./docs/
```

Сверяет суммы, реквизиты, ссылочность между `contract.md`,
`act.md`, `invoice.md`, `bill.md`. Сохраняет
`./reports/reconcile-report-[дата].md`.

#### Финансовый и налоговый контроль

```text
/financial-tax-check ./docs/
````

Проверяет НДС, арифметику, условия оплаты. Сохраняет
`./reports/finance-report-[дата].md`.

#### Проверка русского языка

```text
/russian-proofreading-check ./docs/act.md
```

Выявляет орфографические, грамматические, пунктуационные
ошибки и описки. **Не изменяет** проверяемый файл. Сохраняет
`./reports/proofreading-report-act.md`.

#### Сравнение версий договора

```text
/version-diff-semantic ./docs/contract-v1.md ./docs/contract.md
```

Показывает изменения в формате «Было → Стало» с группировкой
по темам и указанием направления (в чью пользу). Сохраняет
`./reports/diff-report-contract-v1-contract.md`.

### Рекомендуемая последовательность для локальной модели

При использовании qwen3.8:27b (медленнее облачной модели)
рекомендуется вызывать навыки явно и по одному:

1. `/financial-tax-check ./docs/` — быстрая проверка арифметики.
2. `/cross-doc-reconcile ./docs/` — сверка сумм и реквизитов.
3. `/contract-legal-review ./docs/contract.md` — глубокий
юридический анализ.
4. `/russian-proofreading-check ./docs/` — вычитка.
5. `/audit-summary ./docs/` — финальный сводный отчёт.

## Навыки

### contract-legal-review

**Триггеры**: «проверь договор», «риски», «юридическая проверка»,
«аудит договора».

**Что проверяет**:

- Ответственность: лимит (cap), неустойки, асимметрия.
- Права: переход прав, объём, open-source, предсуществующие права.
- Расторжение: односторонний отказ, приёмка, cure period.
- Gap-анализ: отсутствующие защитные пункты (NDA, гарантии).

**Выход**: `./reports/audit-report-[имя].md` с уровнями 🔴/🟡/🟢.

### cross-doc-reconcile

**Триггеры**: «сверить документы», «проверить закрывающие»,
«сравнить акт и договор».

**Что проверяет**:

- Суммы: Акт ↔ Договор/Спецификация, Счёт ↔ Акт.
- Реквизиты: ИНН, КПП, расчётные счета, адреса.
- НДС: ставка и расчёт во всех документах.
- Ссылочность: на какой договор/приложение ссылается акт.
- Подписанты: соответствие должностей договору.

**Выход**: `./reports/reconcile-report-[дата].md`.

### financial-tax-check

**Триггеры**: «проверить НДС», «проверить суммы»,
«финансовая проверка».

**Что проверяет**:

- Ставка НДС: 22% / 0% / без НДС — обоснованность.
- Арифметика: net + vat = gross (допуск 1 рубль).
- Совпадение сумм между документами.
- Условия оплаты: счёт ↔ договор.
- Реквизиты налогового учёта: ИНН продавца/покупателя.

**Выход**: `./reports/finance-report-[дата].md`.

### russian-proofreading-check

**Триггеры**: «проверить орфографию», «вычитать», «найти
опечатки», «проверка пунктуации».

**Что проверяет**:

- Орфография: правописание слов по академическому справочнику
- под ред. Лопатина.
- Грамматика: согласование, управление, склонение.
- Пунктуация: запятые, тире, двоеточия.
- Описки: пропуск/замена/перестановка букв.

> **Важно**: не изменяет проверяемые файлы.

**Выход**: `./reports/proofreading-report-[имя].md`.

### version-diff-semantic

**Триггеры**: «что изменилось», «сравни версии», «diff договора».

**Что проверяет**:

- Суммы и финансы.
- Сроки.
- Ответственность.
- Интеллектуальные права.
- Расторжение и приёмка.
- Скрытые изменения («и» → «или», «обязан» → «вправе»).

**Выход**: `./reports/diff-report-[старая]-[новая].md` в формате
«Было → Стало» с указанием направления (в чью пользу).

### audit-summary

**Триггеры**: «полный аудит», «проверить всё», «сводный отчёт».

**Что делает**: последовательно применяет инструкции
`contract-legal-review`, `cross-doc-reconcile`,
`financial-tax-check`, `russian-proofreading-check` и
агрегирует результаты.

**Выход**: `./reports/audit-report-[проект].md` с вердиктом
(готов / требует исправления / блокирован).

## Ограничения

### Технические

- **Локальная модель медленнее облачной**. Полный аудит
комплекта из 4 документов может занимать несколько минут.
- **Контекстное окно**. При очень длинных договорах (>50 000
слов) возможна потеря деталей. Рекомендуется разбивать
проверку по разделам.
- **Качество конвертации PDF**. Таблицы и сложное
форматирование могут искажаться при конвертации в Markdown.
Навыки отмечают такие случаи как «требует ручной проверки».

### Юридические

- **Агент не юрист**. Отчёты носят вспомогательный характер
и не заменяют проверку квалифицированным юристом.
Это предупреждение включено в каждый отчёт.
- **Налоговое законодательство меняется**. Навык
financial-tax-check проверяет НДС по ставке 22% (c 2026),
но при изменении законодательства требует обновления.
- **Локальные модели могут ошибаться**. В сомнительных случаях
навык помечает результат как «требует проверки по словарю»
или «требует ручной проверки», а не выдаёт предположение
за факт.

### Ограничения по данным

- **Конфиденциальность**. При использовании облачной модели
(gpt-oss:120b-cloud) документы отправляются на серверы
Anthropic/провайдера. Для конфиденциальных договоров
используйте локальную модель.
- **Не коммитьте документы**. Реальные договоры содержат
персональные и коммерческие данные.

## Разработка

### Добавление нового навыка

1. Создайте директорию `.claude/skills/<имя-навыка>/`.
2. Создайте `SKILL.md` со структурой:

```yaml
---
name: <имя-навыка>
description: |
  <что делает>. Используй, когда пользователь просит
  <триггеры>.
allowed-tools: Read, Glob, Grep, Write
argument-hint: <подсказка>
---
```
3. Опишите алгоритм, формат отчёта, правила и обработку
ошибок.
4. Проверьте вызов: `/имя-навыка <аргументы>`.
5. Добавьте раздел в README.

### Тестирование навыка

```bash
# Создайте тестовый набор документов
mkdir -p test/fixtures
cp docs/contract.md test/fixtures/

# Запустите агента и вызовите навык
ollama launch claude --model qwen3.8:27b
# В чате:
/contract-legal-review test/fixtures/contract.md
```

### Стиль SKILL.md

- Frontmatter: `name`, `description`, `allowed-tools`,
`argument-hint`.
- `description` — в третьем лице, с ключевыми словами-триггерами.
- Инструкции — пошаговые, с явными критериями критичности.
- Правила — запрет на выдумывание, различение «отсутствует» и
«неверно», цитирование источника.
- Формат отчёта — с таблицей сводки и уровнями 🔴/🟡/🟢.

### Контрибьюции

1. Форкните репозиторий.
2. Создайте ветку: `git checkout -b feature/new-skill`.
3. Внесите изменения, проверьте на тестовых документах.
4. Убедитесь, что `.gitignore` исключает реальные документы.
5. Отправьте pull request с описанием изменений.
