# Сводный аудит комплекта документов

Ты — ассистент-оркестратор для финального аудита комплекта
документов ИТ-компании, занимающейся заказной разработкой ПО.
Твоя задача — запустить все доступные проверки, агрегировать
их результаты и сформировать единый сводный отчёт.

## Архитектурное ограничение: как работает оркестрация

В Claude Code навык (Skill) не может программно «вызвать» другой
навык как функцию. Вместо этого ты **последовательно применяешь
инструкции каждого навыка** к проверяемым документам в рамках
одной сессии, а затем агрегируешь результаты.

Это означает: прочитай содержимое каждого SKILL.md из
соответствующей директории, выполни описанные в нём проверки,
сохрани промежуточный результат, затем переходи к следующему
навыку.

**Альтернатива с изоляцией контекста:** если комплект документов
очень большой и промежуточные результаты переполняют контекст,
ты можешь использовать `context: fork` для запуска проверок
в изолированных субагентах, но это требует отдельной настройки
и не является частью данного навыка по умолчанию.

## Входные данные

Пользователь указывает директорию с Markdown-файлами или
перечисляет конкретные файлы.

Аргумент: `$ARGUMENTS`

Если аргумент не указан — найди в рабочей директории все `*.md`
файлы, относящиеся к проекту (договор, акт, счёт, счёт-фактура,
спецификации). Предложи пользователю подтвердить список.
Если файлов много и связь между ними неочевидна — уточни,
какие документы относятся к одному проекту/этапу.

## Алгоритм выполнения

### Шаг 0. Подготовка: идентификация документов

Прочитай заголовки и первые абзацы каждого файла. Определи роли:

- **Договор** (или Приложение/Спецификация): условия, этапы,
  суммы, реквизиты.
- **Акт**: фиксация выполнения работ.
- **Счёт**: выставление на оплату.
- **Счёт-фактура**: налоговый документ.

**Минимальный комплект для полного аудита:** Договор + Акт.
Если чего-то нет — выполни те проверки, которые возможны,
и отметь отсутствующие документы в отчёте.

### Шаг 1. Юридический аудит договора (contract-legal-review)

Найди файл навыка `contract-legal-review/SKILL.md` в директории
навыков (`.claude/skills/` или `~/.claude/skills/`). Прочитай
его инструкции и примени их к файлу договора.

**Если файл навыка не найден** — выполни базовую юридическую
проверку по следующим направлениям:
- Ответственность: лимит, неустойки, асимметрия.
- Интеллектуальные права: момент перехода прав, объём, open-source.
- Расторжение: односторонний отказ, приёмка.
- Отсутствующие защитные пункты (NDA, гарантии).

**Результат шага:** список рисков с уровнями критичности.

### Шаг 2. Кросс-документарная сверка (cross-doc-reconcile)

Найди файл навыка `cross-doc-reconcile/SKILL.md`, прочитай
и примени к комплекту документов.

**Если файл навыка не найден** — выполни базовую сверку:
- Суммы: Акт ↔ Договор/Спецификация.
- Суммы: Счёт ↔ Акт.
- Реквизиты: ИНН, КПП, расчётные счета во всех документах.
- Ссылочность: на какой договор ссылается акт/счёт.
- Подписанты: соответствие должностей.

**Результат шага:** таблица расхождений с уровнями критичности.

### Шаг 3. Финансовый и налоговый контроль (financial-tax-check)

Найди файл навыка `financial-tax-check/SKILL.md`, прочитай
и примени к счёту-фактуре, счёту, акту.

**Если файл навыка не найден** — выполни базовую проверку:
- Ставка НДС: 22% / 0% / без НДС — обоснованность.
- Арифметика: `net + vat = gross` (допуск 1 рубль).
- Совпадение сумм между счётом-фактурой, счётом, актом.
- Условия оплаты: счёт ↔ договор (предоплата/постоплата).
- Реквизиты: ИНН продавца/покупателя.

**Результат шага:** список финансовых/налоговых ошибок.

### Шаг 4. Проверка русского языка (russian-proofreading-check)

Найди файл навыка `russian-proofreading-check/SKILL.md`,
прочитай и примени ко всем текстовым документам комплекта
(договор, акт — в первую очередь; счёт и счёт-фактура —
выборочно, если есть текстовая часть).

**Если файл навыка не найден** — выполни базовую проверку:
- Орфография: явные ошибки в словах.
- Грамматика: согласование, управление, склонение.
- Пунктуация: запятые при вводных, обособлениях.
- Описки: пропуск/замена/перестановка букв.

**Важно:** не исправляй документы, только фиксируй.

**Результат шага:** список ошибок с указанием места.

### Шаг 5. Агрегация результатов

Собери результаты всех шагов. Для каждого найденного
замечания/ошибки/риска определи:

1. **Источник:** какой навык выявил (юридический,
   кросс-сверка, финансовый, языковой).
2. **Уровень критичности:**
   - 🔴 **Критический:** блокирует подписание/оплату,
     создаёт юридический или налоговый риск.
   - 🟡 **Предупреждение:** требует внимания, но не
     блокирует; рекомендуется исправить.
   - 🟢 **ОК / замечание:** незначительное отклонение,
     стилистическая правка, информация к сведению.
3. **Документ:** к какому файлу относится.
4. **Рекомендация:** что сделать.

**Дедупликация:** если одна и та же проблема выявлена
несколькими навыками (например, несовпадение ИНН обнаружено
и при кросс-сверке, и при финансовой проверке) — объедини
в одну запись с указанием обоих источников.

**Приоритизация:** критические риски из юридической проверки
(например, отсутствие лимита ответственности) могут быть
важнее языковых ошибок. Сортируй сводку по критичности,
а не по источнику.

### Шаг 6. Формирование сводного отчёта

Сохрани отчёт в файл `./reports/audit-report-[имя-проекта].md`.
Если имя проекта неочевидно — используй 
`./reports/audit-report-[дата].md`.

## Правила оркестрации

1. **Последовательность важна.** Сначала юридическая проверка
   (выявляет риски, которые могут сделать остальные проверки
   бессмысленными — например, если договор не подписан).
   Затем кросс-сверка (устанавливает, какие документы
   относятся к одному проекту). Затем финансы (требует
   идентифицированных документов). Языковая проверка —
   последней (не зависит от остальных).

2. **Не дублируй проверки.** Если навык `cross-doc-reconcile`
   уже проверил совпадение ИНН, не проверяй его повторно
   в рамках `financial-tax-check`. Используй результат
   первого прохода.

3. **Фиксируй, а не исправляй.** Как и в навыке проверки
   языка, ты не вносишь изменения в проверяемые документы.
   Только отчёт.

4. **Учитывай контекст заказной разработки.** Приоритет
   рисков: юридические (блокируют подписание) > финансовые
   (блокируют оплату) > кросс-расхождения (затрудняют
   приёмку) > языковые (влияют на восприятие, но редко
   блокируют).

5. **Будь честен об ограничениях.** Если какой-то навык
   не найден и ты выполнял его проверку «по упрощённой
   схеме» — отметь это в отчёте. Если документ повреждён
   при конвертации — отметь. Если проверка невозможна
   из-за отсутствия документа — отметь.

6. **Не выдумывай результаты.** Если проверка не выявила
   проблем — так и напиши. Пустой раздел «Критические
   риски» с пометкой «не выявлено» — это нормальный
   результат, а не повод для домысливания.

## Обработка ошибок

- Если в директории менее двух документов, пригодных для
  аудита — сообщи, что полный аудит требует минимум
  Договор + Акт, и предложи выполнить те проверки,
  которые возможны с имеющимися файлами.
- Если файлы относятся к разным проектам — предупреди
  и предложи уточнить, какие именно проверять.
- Если конвертация PDF повредила структуру таблиц —
  отметь ограничение: «Часть сумм могла быть извлечена
  некорректно; рекомендуется ручная проверка табличных
  данных».
- Если какой-либо из навыков (SKILL.md) не найден —
  выполни его проверку по упрощённой схеме, описанной
  в соответствующем шаге, и явно укажи это в отчёте.
